# Scoring Rubric (100 points)

| Area | Points | Full-credit evidence |
|---|---:|---|
| Programming/debugging | 25 | Persistent update, correct deletion/404, whitespace validation, focused tests |
| API/Database | 20 | Correct validated filter, parameterised SQLite access, JSON/status correctness, SQL inspection |
| Git | 10 | Feature branch, 2+ logical commits, clear history and summary |
| Docker/Linux | 15 | Build/run/health verification, persistence, useful Linux diagnostics/logs |
| CI/CD | 15 | Valid ordered GitLab test/build pipeline plus one useful improvement |
| Troubleshooting/Integration | 10 | Verified webhook JSON, graceful failure, evidence-based diagnosis |
| Problem solving | 5 | Small, readable, well-explained changes within timebox |

## Scoring guidance

- Award partial credit for a working subset; do not require a specific coding style.
- Deduct points only for missing, incorrect, or unverified work in the relevant row.
- A solution that breaks the existing health/create/read flow cannot score above 50 until restored.
- A candidate who documents a limitation and verifies all other work should receive credit for demonstrated skills.
